# מתאם המגרשים — modiin-planner

כלי פשוט לעדכון ופרסום זמינות אולמות הספורט. אבא מעדכן פעם בשבוע (ביום שישי) את
הזמינות לשבוע הקרוב, ולוחץ "שמירה ופרסום" — הקבוצות, המאמנים והמשפחה רואים לוח
עדכני תמיד באותו קישור, בלי שצריך לנסח מחדש הודעת וואטסאפ כל שבוע.

## מבנה

- **`/`** — הלוח המפורסם (ציבורי, ללא התחברות): תצוגת שבוע רגילה + פוסטר לשיתוף
  כתמונה + טקסט מוכן להעתקה לוואטסאפ.
- **`/login`** — כניסת מנהל עם קוד גישה (PIN).
- **`/admin`** — מסך העדכון (מוגן בהתחברות): לוח שנה לכל אולם, סגירה זמנית ברמת
  שבוע או יום בודד, הודעות מנהלה.

הנתונים נשמרים ב-Postgres (טבלה יחידה עם `JSONB`), ונקראים מחדש בכל טעינת עמוד —
אין צורך ב-build מחדש כדי לפרסם עדכון.

## הרצה מקומית

```bash
npm install
cp .env.example .env.local
# מלאו ב-.env.local:
#   DATABASE_URL   — כתובת חיבור ל-Postgres (למשל מ-Neon/Vercel Postgres)
#   ADMIN_PIN      — קוד הגישה למסך העדכון
#   SESSION_SECRET — מחרוזת אקראית, לדוגמה: openssl rand -hex 32
npm run dev
```

## פריסה ל-Vercel

1. חברו את המאגר הזה לפרויקט ב-Vercel (זה כבר נעשה אם קיבלתם הודעה על כך).
2. בפרויקט ב-Vercel: **Storage → Create Database → Postgres** (מבוסס Neon,
   כלול בתוכנית ה-Hobby). זה יגדיר אוטומטית את `DATABASE_URL` (או `POSTGRES_URL`)
   בפרויקט.
3. **Settings → Environment Variables**: הוסיפו `ADMIN_PIN` ו-`SESSION_SECRET`.
4. **Storage → Create Database → Blob**, עם **Access: Public** (חשוב — לא Private!),
   ובחיבור לפרויקט תנו לו את ה-**Prefix** `IMAGES` (כך שהמשתנה שנוצר יהיה
   `IMAGES_READ_WRITE_TOKEN`). זה משמש להעלאת תמונת הפוסטר לצורך כפתור
   "פרסם בוואטסאפ".
5. פריסה מחדש (Redeploy) כדי שהמשתנים ייכנסו לתוקף.

## פיתוח נוסף

- `src/lib/scheduleLogic.ts` — כל הלוגיקה הטהורה (חישובי שעות, ימים, חפיפות,
  טקסט לוואטסאפ) — משותפת בין מסך העדכון לעמוד המפורסם.
- `src/lib/types.ts` — מבנה הנתונים (`ScheduleState`, `Hall`, `Slot`).
- `src/lib/db.ts` — קריאה/כתיבה מה-Postgres.
- `src/lib/auth.ts` — התחברות מבוססת קוד גישה + עוגיית סשן חתומה.
